# i18n package overview

## Purpose
The `i18n/` package is a small, data-only workspace package that centralizes:
- The list of supported locales (and their display names).
- A generated catalog of shared translation keys used across the game.

It intentionally does **not** contain runtime translation logic. Runtime translation and locale switching live in `hera/i18n/`, while translation tables are generated by `codegen/`.

## Public surface

### `AvailableLanguages.tsx`
Defines the supported locale codes and labels:

- `AvailableLanguages`: `Map<LocaleCode, DisplayName>`
  - Example keys: `en_US`, `de_DE`, `ja_JP`, `zh_CN`, `pt_BR`, `uk_UA`.
  - Values are human-readable language names (localized in the language itself).
  - Map preserves insertion order, which matters for UI display order.
- `AvailableLanguage` type
  - Derived from the `AvailableLanguages` key type via a conditional type.
  - Used to constrain locale strings at compile time.

This is the only runtime-facing API currently used in the open-source repo.

### `Common.ts`
```ts
export { default } from './Entities.ts';
```
`Common.ts` is a stable re-export of the generated translation catalog so callers can import `@deities/i18n/Common` without coupling to the generated file name. The actual file (`Entities.ts`) is created by codegen and is not committed in this OSS snapshot.

### `Entities.ts` (generated)
Generated by `codegen/generate-translations.tsx` into `i18n/Entities.ts`.

Shape:
```ts
export default {
  "StringKey": "Translator hint string",
  ...
};
```

Keys are unique entity/map names (and related labels) that should be translated. Values are short hints to disambiguate the context for translators (e.g. `"Building name"`, `"Map name (Only translate map names if it helps with understanding)"`).

## Data flow and generation

### Build-time generation pipeline
`pnpm codegen` runs `codegen/generate-translations.tsx`, which:
1. Reads authoritative game data:
   - `athena/info/*` (buildings, units, tiles, decorators, weapons, movement types)
   - Map fixtures in `hermes/map-fixtures/` and `fixtures/map/`
2. Extracts display names and map names.
3. Deduplicates names across categories so each string is translated once.
4. Emits a single shared catalog at `i18n/Entities.ts`.

The generator formats and signs the file for stable, reproducible output.

### Runtime consumption
`i18n/` itself is data-only. Runtime usage happens in `hera/`:
- `hera/i18n/LocaleContext.tsx` imports `@deities/i18n/AvailableLanguages` to:
  - Validate/select locales in `fbtee`’s locale context.
  - Drive UI locale selection order.
  - Coordinate locale-driven font selection via `ui/CSS.tsx`.

Translation maps for specific entity names/descriptions and message vocabularies are generated into `hera/i18n/*Map.tsx`. Those maps are used by `hera/i18n/injectTranslation.tsx` and `hera/i18n/translateMessage.tsx` at runtime, but `i18n/Entities.ts` is the shared, package-level catalog used to build translation dictionaries.

## Interactions with other packages

- `codegen/`
  - Produces `i18n/Entities.ts` from canonical data in `athena/` and `hermes/`.
- `hera/`
  - Consumes `@deities/i18n/AvailableLanguages` for locale setup and UI.
  - Consumes related generated translation maps (`hera/i18n/EntityMap.tsx`, `CampaignMap.tsx`, `MessageMap.tsx`) that are derived from the same source data as `i18n/Entities.ts`.
- `athena/` + `hermes/`
  - Provide the canonical entity names and map fixtures that become translation keys.

In the OSS repo snapshot, `i18n/Entities.ts` is absent until `pnpm codegen` is run.

## Porting / reuse notes

If recreating this package in another language or game:
- Keep locale identifiers stable; they are part of the public API (storage keys, asset selection, language packs).
- Treat canonical game data as the single source of truth for translation keys.
- Generate a **deduplicated** string catalog with clear translator hints to reduce duplicate work.
- Separate concerns:
  - `i18n/` (shared catalog + locale list)
  - Client runtime (locale context, text injection, translation maps)
- Favor deterministic generation with stable output so translation workflows can cache and diff reliably.
